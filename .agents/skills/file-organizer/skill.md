name: file-organizer
description: Organize the files in the given directory according to the process outlined below.
---

## Process:

1. Before organizing the files, reflect on the full conversation and extract the user’s real goal for the organization. Identify the core intent, the most important entities, and the main retrieval needs the final structure should support. Determine what would make the collection feel immediately understandable and useful: fast lookup, chronological browsing, project tracking, client-based access, topic grouping, document-type separation, version clarity, archival cleanliness, or some combination. Translate this into clear priorities: what must be obvious from the filenames, what must be obvious from the folder structure, and what can remain secondary.

2. Design the naming scheme before renaming anything. If the user provides a naming convention, follow it closely and apply it consistently across the full file set. If they do not provide one, create a naming scheme that best captures the goal of the organization and makes files easy to identify without opening them. The naming scheme should preserve the most important distinctions, such as date, project, topic, client, file type, version, or status. Names should be clean, uniform, readable, and sortable, with enough specificity to distinguish similar files while avoiding unnecessary clutter.

3. Design the folder hierarchy as a deliberate taxonomy, not just a pile of categories. Choose how deep or shallow the hierarchy should be based on the size, complexity, and likely future use of the collection. Use a shallow structure when simplicity is best. Use multiple levels when deeper grouping makes the system more intuitive and reduces clutter. The hierarchy should make it immediately obvious where to find things, grouping first by the most meaningful retrieval dimension and then by secondary dimensions. Related files should stay together, ambiguous files should be placed thoughtfully, and catch-all folders should be minimized.

4. Rename and reorganize the files into the new structure. Apply the naming scheme consistently, move files into the folder hierarchy, and handle edge cases carefully. Clean up vague names, inconsistent formatting, duplicates, and unnecessary noise while preserving important meaning. Infer categories from filenames, metadata, contents, extensions, or surrounding context when needed. The final result should feel like it was organized by someone who deeply understood the user’s goal and built a system that is intuitive, legible, and scalable.

5. Zip the fully reorganized folder structure into a single downloadable archive and give the user a link to download it.

6. Briefly explain the logic of the organization: the naming scheme used, the folder hierarchy created, and any important judgment calls made for ambiguous files, duplicates, or unusual cases.

## Output:

**ALWAYS produce a fully reorganized file collection with renamed files, a clear folder hierarchy, and a downloadable zip archive. Creating the organized structure and returning it as a zip file is the entire purpose of this skill. The user must get a clean, intuitive, ready-to-download result.**
